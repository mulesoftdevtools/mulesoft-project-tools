HTTP Status & Mule Error Reference

Every HTTP status code you are likely to meet in an integration, with the Mule 4 error type it raises: the HTTP connector type thrown by an HTTP Request operation (for example HTTP:NOT_FOUND) and the APIkit type thrown by the router (for example APIKIT:BAD_REQUEST). Each row also says whether a retry with Until Successful is likely to help. Click any error type to copy it into an on-error handler.

How to use this tool

  1. Search by code, name, error type or keyword — for example 429, timeout or APIKIT.
  2. Filter by class (2xx, 4xx, 5xx…) to narrow the list.
  3. Click an error type to copy it, then paste it into the type of an On Error Continue / Propagate scope.
  4. Use the Retry? column to decide which errors belong inside Until Successful.

HTTP connector error types without a status code

Example: handle a 404 from a downstream API

<error-handler>
  <on-error-continue type="HTTP:NOT_FOUND">
    <ee:transform>
      <ee:message>
        <ee:set-payload><![CDATA[%dw 2.0
output application/json
---
{ message: "Order not found" }]]></ee:set-payload>
      </ee:message>
      <ee:variables>
        <ee:set-variable variableName="httpStatus">404</ee:set-variable>
      </ee:variables>
    </ee:transform>
  </on-error-continue>
  <on-error-propagate type="HTTP:TIMEOUT, HTTP:CONNECTIVITY, HTTP:SERVICE_UNAVAILABLE">
    <logger level="ERROR" message="#['Downstream unavailable: ' ++ error.description]"/>
  </on-error-propagate>
</error-handler>
Mappings follow the Mule 4 HTTP connector and APIkit documentation. Statuses without a dedicated type still fail the request when they are outside the response validator's success range — catch them with a parent type and inspect error.errorMessage.attributes.statusCode.
